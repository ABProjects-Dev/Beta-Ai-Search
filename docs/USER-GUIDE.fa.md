# راهنمای نصب و استفاده Beta AI Search

## ۱. پیش‌نیازها

- WordPress 6.6 یا جدیدتر؛ PHP 8.1 یا جدیدتر با افزونه‌های `mbstring` و `OpenSSL`.
- WooCommerce 8.2 یا جدیدتر، فعال پیش از افزونه.
- Elementor Free برای ویجت drag & drop؛ Elementor Pro برای هسته لازم نیست.
- کلید API حداقل یک سرویس دارای Embedding و یک سرویس دارای Query Understanding. این دو می‌توانند متفاوت باشند.
- در production، cron سیستمی وردپرس را فعال کنید تا ایندکس پس‌زمینه به ترافیک مرورگر وابسته نباشد.

نسخه‌های واقعاً آزمون‌شده در `TEST-REPORT.fa.md` آمده‌اند. حداقل نسخه به معنی تست همه ترکیب‌ها نیست.

## ۲. نصب

1. فایل ZIP افزونه را از مسیر WordPress → Plugins → Add New → Upload Plugin نصب کنید، یا پوشه `beta-ai-search` را در `wp-content/plugins/` قرار دهید.
2. WooCommerce را فعال کنید، سپس Beta AI Search را فعال کنید.
3. از منوی Beta AI Search → Settings → AI providers کلیدهای API را وارد کنید. کلیدها فقط در سرور ذخیره می‌شوند و در JavaScript مرورگر قرار نمی‌گیرند.
4. در تب Embedding model یک مدل دارای قابلیت embedding انتخاب کنید. حالت Auto فقط مدل‌های declared-capable را در نظر می‌گیرد.
5. در تب Query understanding یک مدل مستقل برای درک درخواست انتخاب کنید. داشتن chat به معنی داشتن embedding نیست.
6. تنظیمات را ذخیره کنید و با دکمه‌های Test connection کلید/مدل را بررسی کنید.
7. به Product index بروید و Start را بزنید. پیشرفت، تعداد پردازش‌شده/باقی‌مانده، Pause، Resume و Full rebuild در همان صفحه است.
8. ویجت «AI Product Search» را در Elementor بالای گرید موجود فروشگاه قرار دهید، یا shortcode زیر را بالای گرید بگذارید:

```text
[beta_ai_search]
```

نمونه هدف‌گیری دقیق گرید موجود:

```text
[beta_ai_search target="#shop-grid ul.products" template="pill" scope="first"]
```

`scope="all"` همه گریدهای منطبق بعدی را به‌روزرسانی می‌کند. هیچ گرید موازی ساخته نمی‌شود.

## ۳. رفتار جستجو

- جستجو فقط با کلیک دکمه یا Enter ارسال می‌شود؛ هنگام تایپ درخواست API ارسال نمی‌شود.
- دکمه × فقط متن را پاک می‌کند. دکمه «حذف فیلتر» گرید را به حالت اولیه برمی‌گرداند.
- کل کاتالوگ منتشرشده بررسی می‌شود؛ دسته فعلی، فیلترهای قبلی فروشگاه و صفحه جاری نتیجه را محدود نمی‌کنند.
- محصول موجود زودتر از ناموجود نمایش داده می‌شود؛ داخل هر گروه ترتیب بر اساس ارتباط است.
- اگر چند variation از یک محصول متغیر منطبق شوند، فقط یک کارت والد نمایش داده می‌شود.
- اگر هیچ تطبیق قابل قبولی وجود نداشته باشد، فقط این پیام نمایش داده می‌شود:

> محصولی مطابق درخواست شما پیدا نشد.

- محصول جایگزین مشابه، پیشنهاد خودکار یا بازنویسی خودکار درخواست برای افزایش نتیجه وجود ندارد.
- خطای AI، کلید نامعتبر، quota، timeout یا پاسخ نامعتبر باعث جستجوی کلمه‌ای پنهان نمی‌شود؛ پیام خطا و «تلاش مجدد» نمایش داده می‌شود و گرید فعلی دست‌نخورده می‌ماند.

## ۴. زبان و متن‌ها

زبان رابط در Settings → Language انتخاب می‌شود: فارسی RTL یا انگلیسی LTR. این انتخاب مستقل از زبان درخواست کاربر است؛ هر دو زبان فارسی و انگلیسی پذیرفته می‌شوند.

همه متن‌های ویجت در Settings → Widget texts مدیریت می‌شوند، نه در تنظیمات هر ویجت: placeholder، دکمه جستجو، loading، نبود نتیجه، حذف فیلتر، خطا، تلاش مجدد، پاک کردن متن، برچسب دسترس‌پذیری، شمارش نتیجه و صفحه قبل/بعد.

## ۵. انعطاف تطبیق

انعطاف عمومی و انعطاف هر ویژگی عددی بین ۰ تا ۱۰۰ است: قیمت، رنگ، برند، سایز، جنس، ویژگی فنی و سایر خصوصیات.

فرمول‌های پذیرش:

```text
g = global_flex / 100
حداقل شباهت معنایی = 0.76 - 0.26*g
حداقل امتیاز کل     = 0.70 - 0.15*g
امتیاز کل = 0.65*semantic + 0.35*mean(attribute scores)
حداقل ویژگی صریح = 1 - 0.5*flex_i
```

اگر ویژگی صریحی در محصول وجود نداشته باشد، مطابق فرض نمی‌شود؛ حتی اگر انعطاف ۱۰۰ باشد. رنگ‌های نزدیک فقط در صورت انعطاف مثبت و طبق نگاشت داخلی امتیاز نرم می‌گیرند. برند و سایز اساساً تطبیق دقیق/alias دارند.

برای قیمت، سرریز پذیرفته‌شده حداکثر `0.25 * flex_price * bound` است. مثال: با انعطاف قیمت ۲۰٪، سقف ۱۰۰ واحد تا ۱۰۵ واحد پذیرفته می‌شود و ۱۰۶ واحد رد می‌شود. محصول بدون قیمت برای درخواست دارای محدودیت قیمت رد می‌شود.

درخواست‌های دارای confidence کمتر از `0.60` در مرحله درک AI به‌عنوان نبود نتیجه بسته می‌شوند. این آستانه با فیلتر `bas_minimum_query_confidence` قابل تنظیم است. این ضرایب اولیه و قابل آزمون‌اند؛ کیفیت نهایی باید روی کاتالوگ و کلیدهای واقعی فروشگاه سنجیده شود.

## ۶. واحد پول و قیمت

عبارت‌های عددی صریح مانند «تا ۲ میلیون تومان»، «بین ۱٫۵ تا ۲ میلیون تومان»، «under 1.5m USD» به‌صورت قطعی parse می‌شوند و بر قیمت استخراج‌شده توسط LLM اولویت دارند.

تبدیل تومان/ریال برای فروشگاه IRT/IRR خودکار است. برای ارزهای دیگر باید نرخ صریح در Settings → General وارد شود. نرخ ساختگی استفاده نمی‌شود؛ در نبود نرخ، خطای تنظیمات نمایش داده می‌شود.

## ۷. ایندکس و به‌روزرسانی

ایندکس در جدول‌های اختصاصی افزونه داخل دیتابیس وردپرس ذخیره می‌شود. منابع پیش‌فرض: عنوان، توضیح کوتاه/کامل، دسته‌ها، برچسب‌ها، ویژگی‌ها، برند، قیمت عادی/حراج، موجودی، وضعیت انتشار، SKU، variationها، taxonomyهای عمومی و فیلدهای سفارشی عمومی allowlistشده. ACF و افزونه‌های جانبی از allowlist و hookهای عمومی عبور می‌کنند. تحلیل تصویر انجام نمی‌شود.

تغییر محصول، قیمت، موجودی، ویژگی، دسته/برند، متای عمومی و variation به صف می‌رود. پس از پایان ایندکس اولیه، تغییرات incremental بدون full scan پردازش می‌شوند. متادیتای protected/internal وارد AI نمی‌شود.

برای production:

```text
DISABLE_WP_CRON را true کنید
یک cron سیستمی برای wp-cron.php یا WP-CLI cron event run تنظیم کنید
```

Worker دارای lease، batch محدود، بودجه زمانی، pause/resume، retry و rebuild است. تغییر مدل/ابعاد embedding نیازمند Full rebuild است و تا پایان موفق، ایندکس قبلی فعال می‌ماند.

## ۸. کش و گزارش‌ها

کش قابل فعال/غیرفعال کردن است و TTL و purge دارد. کلید کش شامل query نرمال‌شده، تنظیمات مؤثر، مدل‌های فعال، endpoint مدل درک درخواست، نسخه ایندکس و واحد فروشگاه است. تغییر محصول/تنظیمات و آزاد شدن صف ایندکس کش را نامعتبر می‌کند.

داشبورد شامل کل جستجوها، موفق، بدون نتیجه، خطا، cache hit، میانگین زمان، مصرف توکن و تفکیک provider/model است. هزینه فقط وقتی محاسبه می‌شود که usage واقعی و نرخ صریح همان مدل وجود داشته باشد؛ در غیر این صورت «نامشخص» است.

ثبت متن جستجو اختیاری است. پیش‌فرض فقط hash نگه داشته می‌شود. IP خام، کلید API، پاسخ خام provider و اطلاعات مشتری در گزارش ذخیره نمی‌شود. Retention گزارش‌ها قابل تنظیم است.

## ۹. امنیت

- کلیدها encrypted at rest هستند؛ برای محافظت بیشتر `BAS_ENCRYPTION_KEY` را در `wp-config.php` تعریف کنید.
- مدیریت با قابلیت `manage_woocommerce` یا `manage_options` و nonce انجام می‌شود.
- ورودی عمومی طول محدود، schema معتبر، prepared statements و rate limit دارد.
- هیچ SQL تولیدشده توسط AI اجرا نمی‌شود.
- خطاها بدون secret و پاسخ خام ثبت می‌شوند.

## ۱۰. حذف افزونه

Deactivate کردن داده‌ها را حذف نمی‌کند. اگر می‌خواهید هنگام Uninstall جدول‌ها و تنظیمات افزونه حذف شوند، Settings → General → Data removal را فعال کنید. در غیر این صورت داده‌ها برای نصب مجدد باقی می‌مانند.

## ۱۱. محدودیت‌های سازگاری

مسیر WooCommerce loop و ویجت Elementor Free در محیط یکپارچه آزمون شده‌اند. مسیرهای Elementor Pro Loop Grid / Products / Archive Products تا آزمون روی نصب واقعی Pro «آزمون‌نشده» هستند. برای گریدهای شخص ثالث از selector دقیق گرید موجود استفاده کنید و سازگاری را بدون تست واقعی ادعا نکنید. جزئیات فنی در `ARCHITECTURE.fa.md` و `DEVELOPMENT.md` است.
